Swift 1.5 vs iQ-MLX: same accuracy, less waiting

Two 4.7-bit MLX packs of the same model on the same runtime: the iQ-MLX pack by ddalcu and the Swift 1.5 fine-tune by Dankpaws. Six suites, two sampling settings, one dot per question.

On an Apple M4 Max, Swift 1.5 gets to the final answer 2.9× faster on GPQA-Diamond and 2.0× faster on LiveCodeBench (median per question), with the same accuracy. Both generate at the same speed (74 vs 74 tokens/s on GPQA). The gain comes from shorter thinking, not from faster generation.

Limits

  • One run per model and sampling setting. GPQA-Diamond and LiveCodeBench are 50-question samples (seed 42), not the full sets, so a difference of 2–3 questions is within run-to-run noise.
  • Times are medians per question. A few answers on both sides run to the max_tokens limit and dominate the totals, so the totals improve less than the medians. The page shows both.
  • The two packs share the same quantization layout but ship different n-gram tables, so this compares the two packs as published, not only the fine-tuned weights.
  • Tool calling: the runner did not record the thinking text. A median of 104–194 tokens per answer suggests little or no thinking in these suites.
  • Instruction following is a 20-case IFEval-style probe. It does not reproduce the IFBench score of the Swift 1.5 model card.
  • Agent quality (for example Terminal-Bench) is not measured.
