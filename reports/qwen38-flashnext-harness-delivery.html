Four coding harnesses, one local model

Claude Code, OpenCode, pi and dsh on a Mac Studio M4 Max, with a standard and an uncensored Qwen3.8 Flash-Next pack

I gave the same 7 coding tasks to 4 agent harnesses, all driving one model that runs on my desk. Then I swapped the weights for an uncensored pack and ran everything again. 105 of 112 sessions finished the task. The harness made no measurable difference, the uncensored pack cost little, and my own benchmark was wrong three times before the numbers held.

What I ran

112 sessions, each one judged by a script

Every session starts from a fresh copy of a small repository and one prompt. The harness runs without permission prompts inside a macOS sandbox, with its own empty home directory. When the harness exits, a hidden script decides whether the task is done: it runs the original tests, probes the behaviour, and looks for shortcuts such as a deleted test.

Question 4 · What does it cost in speed?

2% to 5% slower per agent turn

2% to 5% slower per agent turn. An agent turn is one request with a warm prompt cache and a short answer: about 5.9 s on the standard pack and 6.2 s on the Heretic v2 pack at 128K. The difference comes from token generation: 110 against 117 tokens per second.

Three patterns: the agent stops before the work is complete, it fixes part of the task, or it removes the obstacle (one session deleted a test). None of these shows up in the transcript as an error. If you run a local agent unattended, check the result with something other than the agent.

Lessons

Three times the benchmark was wrong

In the first run, 36 of 112 records were affected by a defect in my harness, not by the model. I found each one by opening the repositories of the failed sessions instead of reading the score.

DEFECT 1

The sandbox broke the linter

What I saw
The environment task scored 0 of 16. 15 sessions were flagged for changing the lint configuration.
Cause
The sandbox hid the .git of the repository above the work copy. The linter walks up the directory tree, hit a permission error (E902) and failed. The agents did the reasonable thing: they changed the configuration to get past it.
Fix
Work copies moved outside any repository. I ran the task again.
0 of 16→13 of 16
DEFECT 2

A cheat detector with a false positive

What I saw
20 records carried the flag “tests modified”, including every session of the 5-step chain.
Cause
The task asks for new tests. A new test extends the import line of the test file, and the detector counted a changed import line as a removed line.
Fix
The detector ignores a changed import line. The verdicts did not move: the original tests always ran from a clean copy.
20 flags→0 flags
DEFECT 3

A rule the prompt never stated

What I saw
7 sessions failed because they set an environment variable in the Makefile. The check wanted the Makefile untouched.
Cause
The prompt forbids weakening the linter or the tests. It says nothing about the Makefile. In all 7 sessions the checks were green and the variable was documented.
Fix
The check now follows the prompt. This one line decided the verdict on the uncensored pack.
47 against 51: fails→51 against 54: passes

Every defect made the model look worse, and every one looked like a model failure in the table. An agent benchmark needs an audit of its failures before its score means anything: read what the agent did, and ask whether the prompt told it not to.

Limits

What this does not show

  • Two repetitions per combination. A gap of 1 or 2 sessions between two harnesses, or of 3 between two packs, is not a result.
  • One model family. Qwen3.8 Flash-Next in one quantization. A weaker model may separate the harnesses.
  • Small tasks. The longest done session took under 6 minutes. Nothing here tests a multi-hour job.
  • Harness versions. Claude Code 2.1.292, OpenCode 1.15.10, pi 0.85.1, dsh 0.1.0-rc.6. OpenCode was one minor line behind the current release.
  • The environment task ran last. Its 16 sessions ran after the fix, not interleaved with the other 96.
  • The refusal probe uses a keyword classifier on the first 300 characters, with a manual check of 60 answers.
  • The checks are mine. I found three defects in them. There may be a fourth.
