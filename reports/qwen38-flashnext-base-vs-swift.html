Base vs Swift 1.5, on mlx-serve and on Splash

Two weights of the same model on two servers: the released Qwen3.8-Flash-Next and the Swift 1.5 fine-tune, each on mlx-serve (MLX packs) and on Splash (GGUF). Accuracy, time and tokens per answer, agent turn by context size, cache, memory, agent tasks, and what has not been measured yet.

The two models score the same; Swift 1.5 gets there with about a third of the tokens. On GPQA-Diamond the base model writes 3.0× the tokens and takes 2.9× the time per question for the same accuracy, on the same server. The engine moves the agent turn more than the model does: at 256K Splash takes 0.71× the mlx-serve turn with Swift, and only Splash serves 1M. On Terminal-Bench 2.1, Swift passes 58/89 on mlx-serve and 57/89 on Splash. The base model on Splash has speed and memory numbers in every band; its quality battery has not run yet, so those cells say so.

6 · Cache hit by scenario

Share of the prompt served from the prefix cache on the next turn. Both engines hit 0.99–1.00 on an identical prompt, an appended message and a tool turn from 128K up. The difference is an edit in the middle of the history: mlx-serve keeps the prefix before the edit (hit 0.41–0.48); Splash recomputes the whole prompt (hit 0), which at 1M costs the 25-minute cold prefill again. Flash-Next is a hybrid model: its recurrent layers carry a state that cannot roll back, and Splash saves that state only at the end of each request.

7 · Memory on 128 GB

Peak wired memory during the probe and the minimum free memory. Splash pins ~16 GB more than mlx-serve at 8K; mlx-serve compresses ~8.5 GB during the load instead. Headroom (128 GB minus wired and compressor peaks) at 256K: 9.8 GB for the base on Splash, 10.1 GB for Swift on Splash, 5.5 GB for Swift on mlx-serve. At 512K mlx-serve needs 4-bit KV and YaRN 2.0 and keeps 3.8 GB of headroom; at 1M it refuses 2–3 of 5 requests after the first. Splash serves 1M with KV int8 and 14.8–16.9 GB of headroom, with the KV past ~860K tokens on SSD.

8 · Agent tasks

Terminal-Bench 2.1: 89 tasks, agent terminus-2, one attempt per task, context 262144, each task's own agent timeout. Only Swift ran it, on both engines. The base model has no Terminal-Bench run: one attempt per task cannot resolve a gap under ~8 tasks, and a run costs ~31 hours of the rig.

Paired: both pass 53, only mlx-serve 5, only Splash 4, neither 27. Exact McNemar p = 1.00: no difference between the two engines with one attempt per task. Median call latency: 11.8 s on mlx-serve, 9.8 s on Splash.

Long agent sessions on mlx-serve 26.10.1 (probes 3b and 3c of the next-steps campaign): 40 tool-loop sessions and 30 turns that grow a session to ~200K tokens. The base model wrote 1.7× the tokens per turn and returned 4 empty answers and 4 wrong code turns past 140K; Swift returned none.

11 · How I measured

  • Rig. Mac Studio M4 Max, 128 GB unified memory, macOS 26.6, no sudo (default wired limit). mlx-serve on port 11234, Splash on 8585.
  • Battery. HumanEval 164, GPQA-Diamond 50 (seed 42), LiveCodeBench v6 50 (seed 42), an IFEval-style probe of 20, and two tool-call suites (40 and 12 cases). temperature 1.0, top-p 0.95, top-k 20, reasoning_effort xhigh, max_tokens 32768–65536. Questions run one at a time. Runners: bench2.py, tool_call_bench.py and if_probe.py of the local-llm-bench submodule; gates by summarize_ab.py.
  • Agent turn. The audit_retrieval fixture at each context size: cold prompt, identical, append, middle mutation and tool turn; T_turn = TTFT of the tool turn + 512 / decode tok/s. Three reps where the table says so. summarize_driver.py and the canonical groups of reports-2026-10.json.
  • Terminal-Bench 2.1. harbor on a MacBook against the rig, agent terminus-2, -n 1, agent timeout 1.0×, build 3.0×, context 262144.
  • Claude Code. claude -p 2.1.292, CLAUDE_CODE_EFFORT_LEVEL=xhigh, four coding tasks, two reps alone per task, request log by a proxy.
  • Effort. GPQA 50 + LCB 50 at low, medium and xhigh; Swift two rounds, base one round at medium and low.
  • Sources. bench/swift15-flashnext-2026-10 (A/B), bench/splash-longctx-2026-10 (Splash, 262K batteries, Terminal-Bench, probes), bench/flashnext-next-steps-2026-10 (effort, agent probes), bench/claude-code-concurrency-2026-11 (Claude Code), bench/engine-updates-2026-10/results/reports-2026-10.json (speed groups).
  • What this page does not measure. The base model's quality on Splash; the base model in agent tasks; more than one run per cell; the full GPQA and LiveCodeBench sets.
