Rig

Setup by candidate

What changes between candidates: runtime, quant, prefix cache mechanism and speculation. Sampling is the same for all of them (vendor): temperature 1.0, top_p 0.95, top_k 20, reasoning xhigh, max_tokens 4096. Fixture audit_retrieval with needles at 10/50/90%. Native context: 262,144 tokens; 512K uses YaRN 2.0. c2 and c3 run the same weights, so they isolate the runtime.

Runtimes compared

All three runtimes do speculative decoding with MTP and prefix caching on Apple Silicon. They differ in where the KV cache lives (RAM, disk or paged SSD) and in how they handle the memory limit: mlx-serve pins it as wired memory, oMLX spills over to SSD and MTPLX refuses the prompt.

Cache hit by scenario

Fraction of the prefix reused in each scenario, for the band's canonical group. cold = first pass (≈0 by design). middle_mutation = the prefix diverges in the middle: oMLX and mlx-serve reuse the intact part (0.30–0.49); MTPLX re-prefills (0.07). append and tool_turn are the gate: ≥ 0.90 at 32K and 128K.
